# Finance App Rules

Проект:
Flutter приложение для учёта личных финансов.

Платформы:
- Android
- Windows

Архитектура:
- UI не должен напрямую работать с SQLite.
- Бизнес-логика отдельно от экранов.
- Использовать понятные модели данных.
- Не ломать существующий функционал без объяснения.

База данных:
- SQLite является основной локальной БД.
- Данные должны быть пригодны для синхронизации в будущем.

Код:
- Всегда показывать полный файл при изменении.
- Не давать кусочные изменения без контекста.
- Перед изменением анализировать связанные файлы.

При изменении кода:
- Для небольших файлов показывать полный файл.
- Для больших файлов показывать полный файл, если изменение затрагивает структуру.
- Не давать отдельные куски кода без объяснения места вставки.
- Перед изменением анализировать связанные файлы.

## Работа с базой данных

SQLite является долгосрочным хранилищем данных.

Не хранить данные только в памяти приложения.

Любая новая сущность должна иметь:
- модель данных;
- таблицу SQLite;
- слой работы с данными;
- UI только через слой логики.

Изменения структуры БД делать через миграции.


## Будущая синхронизация

Архитектура должна учитывать возможную синхронизацию:
- между Android и Windows;
- с облачным хранилищем;
- экспорт и импорт данных.

Не привязывать бизнес-логику к конкретной платформе.
