## Назначение

Показывает, где проект находится прямо сейчас: что готово, что в работе, что болит. Для быстрого ввода в контекст.

---

## Общая информация

**LifeOS** — операционная система для жизни на Flutter.

**Цель:** Перенести управление всеми сферами жизни из разрозненных инструментов в единую локальную систему с AI-ассистентом.

**Главный принцип:** финансовое состояние считается из операций. AI не заменяет мышление, а помогает структурировать, находить связи и замечать закономерности.

---

## Общий статус

- [x] Базовая рабочая версия с управлением счетами, настройками и фоновыми задачами
- [x] Система знаний (Memory): индексация и семантический поиск по чекам и Obsidian
- [x] Переводы между счетами (UI-точки входа добавлены)

- [ ] **Финансовое ядро в процессе завершения:** счета, операции, переводы — готово. Бюджет, долги, планы покупок, пользовательские поля — в разработке/планируются.

## Что реализовано

### Операции

- [x] Расходы и доходы
- [x] Поля: сумма, дата, тип, комментарий, магазин, способ оплаты, связь с чеком
- [x] Хранение, список, удаление (свайпом), привязка к счету
- [x] **Переводы между счетами** — создание перевода через иконку на карточке счёта (↔) или через отдельную FAB на экране операций

### Чеки

- [x] Загрузка фото → AI → Receipt + ReceiptItem
- [x] Создание, просмотр, редактирование чека и товаров, перерасчёт суммы, удаление

### Счета

- [x] Создание, редактирование (ограниченное), удаление, основной счёт
- [x] Операции привязаны к счёту (`accountId`)
- [x] Баланс считается через `FinancialCalculator`
- [ ] ❌ **Полная настройка счетов** (все поля, включая тип, с миграцией данных) — не реализована

### Настройка цветов карточек

- [x] 8 типов счетов (включая 5 пользовательских), светлая/тёмная тема
- [x] Сохранение через `CardColorSettingsRepository`

### AI профили и ключи

- [x] Профили `free` и `paid`, авто-выбор ключа
- [x] Блокировка при ошибках на 10 минут
- [ ] ❌ **Выбор AI-модели в UI** — отсутствует

### Система знаний (Memory)

**Реализовано:**

- [x] Модели, репозитории, сервисы (индексация, эмбеддинги, поиск)
- [x] Хранение в SQLite (таблицы `embeddings`, `memory_notes`)
- [x] Автоиндексация при создании/редактировании чека
- [x] Ручная переиндексация с выбором источников
- [x] Интеграция Obsidian Vault (индексация .md файлов)
- [x] Символьный чанкинг (maxChunkChars = 8000, overlapChars = 200)
- [x] Валидация размера файла (максимум 5 МБ)
- [x] Retry-механизм для API (3 попытки с exponential backoff, без retry для 402)
- [x] Очередь индексации (`IndexingQueue` с параллельностью 3)
- [x] Таблица `indexing_state` для сохранения прогресса (БД `finance_memory.db`, версия 4)
- [x] Фильтрация служебных папок (`.trash`, `.obsidian`, `.git`, `.stversions`)
- [x] Очистка битых векторов при инициализации и поиске
- [x] Валидация текста перед созданием эмбеддингов
- [x] **Индексация пользовательских полей (текст/select)** — добавлена

**Проблемы (требуют исправления):**

- [ ] ⚠️ **OOM при индексации больших Vault** (≥ 600 файлов) — очередь не предотвращает пиковую нагрузку
- [ ] ⚠️ **Валидация текста не работает** — тексты < 10 символов всё ещё отправляются в API
- [ ] ⚠️ **Эмбеддинги «исчезают»** при смене экранов — требуется расследование
- [ ] ⚠️ **Возобновление после перезапуска не работает** — индексация начинается заново
- [ ] ⚠️ **UI управления индексацией отсутствует** — индикатор прогресса не кликабельный, нет паузы/возобновления/отмены
- [ ] ⚠️ **Таск-менеджер отображается на главном экране** — должен показываться только на экране Memory
- [ ] ❌ **Retry-механизм не подтверждён** — отсутствуют логи о повторных попытках

## Архитектурное состояние

Слои: Presentation → Application Logic → Domain → Repository → Data → External Services.

Паттерны: Repository, Service, Feature-based модульность.

**Принятые архитектурные решения (август 2026):**

- [x] Категория — только у ReceiptItem (у чека нет категории)
- [x] Долг — отдельная сущность (не часть Financial State)
- [x] Погашение долга → Operation типа `debt_repayment`
- [x] Бюджетный период — пользовательский (по умолчанию от зарплаты)
- [x] Просроченное не исчезает — всегда видно до ручного закрытия
- [x] Пользовательские поля — метаданные (не влияют на финансы)
- [x] Категории, долги, бюджет, пользовательские поля — добавлены в модель данных

**Ключевые архитектурные решения (требуют завершения):**

- `memory_notes` перенесены в отдельную БД `finance_memory.db` (версия 4)
- Таблица `indexing_state` добавлена в `MemoryDatabase`
- Внедрена очередь индексации (`IndexingQueue`) с параллельностью 3
- Используется символьный чанкинг (8000 символов на чанк)
- `sqlite-vec` временно удалён из `main.dart` (вынесен в отдельную инициативу)

## Текущие ограничения

### Архитектурные

- [ ] Memory требует перехода к универсальной системе знаний (абстракция `KnowledgeSource`)
- [ ] Отсутствует `Receipt Draft` для объединения нескольких фото в один чек
- [ ] Полная настройка счетов не реализована
- [ ] Модуль `custom_fields` требует реализации (планируется в Phase 11)

### Функциональные

- [ ] Качество семантического поиска требует доработки
- [ ] Выбор AI-модели в UI отсутствует
- [ ] Не реализованы: бюджеты, аналитика, графики, долги, подписки, планы покупок
- [ ] Система питания и инвентаризация — не реализована
- [ ] Пользовательские поля — только в планах (Phase 11)

### UI и настройки

- [ ] Не все параметры вынесены в UI (срок хранения фото, удаление свайпом и др.)
- [ ] Data Quality Score не реализован

### Конфиденциальность и монетизация

- [ ] Требуется аудит внешних вызовов
- [ ] Не определён точный список платных функций

## Ближайшие задачи (в порядке приоритета)

1. **Устранить OOM** — пересмотреть ограничения параллелизма и стратегию обработки больших файлов
2. **Расследовать исчезновение эмбеддингов** — проверить жизненный цикл репозиториев и провайдеров
3. **Исправить валидацию текста** — убедиться, что тексты < 10 символов не отправляются в API
4. **Реализовать сохранение состояния** — интеграция `IndexingStateRepository` в `IndexingService`
5. **Добавить UI управления** — кликабельный индикатор с диалогом паузы/возобновления/отмены
6. **Переместить таск-менеджер** — отображать статус индексации только на экране Memory
7. **Добавить логирование retry-механизма** — для подтверждения его работы
8. **Провести повторное полное тестирование** всех сценариев индексации и поиска
9. **Phase 5 — Бюджетные периоды** (план/факт, остатки)
10. **Phase 4 — Долги и обязательства** (Debt + RecurringPayment)
11. **Phase 11.1 — Пользовательские поля для операций**
