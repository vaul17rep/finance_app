## Основные финансовые принципы

### 1. Операции — источник истины
Нельзя: Карта Сбер = 15000 и менять число
Правильно: Доход +50000 → Расход -5000 → Перевод -3000 → Расчёт состояния
Баланс — результат обработки операций.

### 2. Финансовая логика отделена от хранения
База хранит факты. Financial Rules определяют, как факты влияют на состояние.

### 3. Financial State — результат расчёта
Не самостоятельный источник. Operation → Financial Rules → Financial State.
Нельзя изменять Financial State напрямую.

### 4. Каждая операция имеет финансовое влияние
Определяет: источник денег, направление движения, изменение состояния.

### 5. Приватность финансовых данных
Финансовые данные являются чувствительными и требуют особой защиты:
- Все операции, счета, чеки хранятся только локально
- Нет облачной синхронизации по умолчанию
- AI-обработка (распознавание чеков) отправляет только фото, данные не сохраняются
- Все внешние вызовы логируются

## Текущие правила реализации

### Типы операций
OperationType.expense, OperationType.income (enum в lib/models/operation_type.dart).

### Расход (expense)
Уменьшает баланс: balance - сумма. Примеры: покупка, оплата услуги.

### Доход (income)
Увеличивает баланс: balance + сумма. Примеры: зарплата, поступления.

### Формула текущего расчёта
balance = income - expenses
Файл: lib/domain/usecases/financial_calculator.dart

### Чеки
Receipt → Expense Operation. Сумма операции = сумме чека.
Файл: lib/data/services/receipt_creation_service.dart

## Расчёт финансового состояния

### Общий поток
Operation → Financial Rules → FinancialCalculator → Financial State

Реализация:
- lib/domain/usecases/financial_calculator.dart — логика расчёта
- lib/domain/usecases/financial_service.dart — сервис
- lib/domain/entities/financial_state.dart — сущность

### Источник данных
Operation History (operation_repository.dart). Financial State не хранится.

### Изменение операций
Нельзя менять баланс напрямую. Изменить операцию → пересчитать Financial State.

## Типы операций

### Legacy (Google Sheets)
Expense, Extra Expense, Income, Extra Income.

### Текущие + планируемые
- Expense — обычный расход, уменьшает состояние
- Extra Expense — доп. расход вне бюджета
- Income — обычный доход, увеличивает состояние
- Extra Income — доп. доход вне регулярных
- Transfer — перемещение между состояниями (не доход/расход). ❓ Статус: не решено.
- Repayment — погашение долга. ❓ Статус: не решено.

## Финансовые состояния

### Общий принцип
Место хранения/учёта денег. Каждое состояние имеет свои правила изменения.

### Дебетовая карта
Доход → баланс+. Расход → баланс-.

### Наличные
Доход → наличные+. Расход → наличные-.

### Кредитная карта
Обязательство перед банком. Покупка → долг+. Погашение → долг-.

## Миграция данных при изменении счёта

### Свободно изменяемые поля (не влияют на операции)
- Название
- Иконка
- Цвет
- Описание
- Порядок
- Основной счёт

### Изменяемые с обработкой последствий (требуют сценария миграции)

**Тип счёта (например, credit → work_benefit):**
- При смене типа необходимо проверить все операции, связанные со счётом
- Если операции есть — показать предупреждение: "Изменение типа счёта повлияет на историю операций. Продолжить?"
- После подтверждения — выполнить миграцию данных (пересчёт категорий, переклассификация операций)
- Если миграция невозможна — заблокировать изменение с объяснением причины

**Начальный баланс:**
- Нельзя просто изменить значение
- Нужен отдельный механизм: создание корректирующей операции (например, "Корректировка начального баланса")
- Или: создание новой операции типа adjustment с комментарием

### Неизменяемые поля
- ID (идентификатор)
- Валюта (изменение валюты = миграция всей финансовой истории, что практически равно созданию нового счёта)

## Долги

### Создание долга
Кредитные карты: покупка с кредитного лимита увеличивает долг.
Личные долги: ❓ не определено.

### Погашение долга
Уменьшает задолженность.

## Бюджет

### Назначение
Планирование и контроль расходов.

### Период бюджета
Legacy: от поступления до поступления (например, 30.05 → 29.06). Статус: не реализован.

### Расчёт доступного остатка
Доступные средства = Текущее состояние − Запланированные расходы. ❓ Формула требует подтверждения.

### Варианты настройки периода (❓ не решено)
A: Фиксированная дата (1 число)
B: От зарплаты до зарплаты
C: Рабочий календарь
D: Пользовательские настройки

## Финансовые ограничения

1. Баланс нельзя менять вручную
2. Финансовая логика не зависит от UI
3. Финансовая логика не зависит от базы данных
4. AI не принимает финансовые решения
5. Финансовые состояния = результат обработки операций
6. Financial State не изменяется напрямую: Operation → Financial Rules → Financial State

## Модель распространения (финансовый аспект)

### Бесплатная версия (полностью функциональна)
- Неограниченное количество операций, счетов, чеков (локально)
- Базовое AI-распознавание чеков (ограниченное количество)
- Базовый семантический поиск (локальные эмбеддинги)
- Все основные настройки
- Локальное хранение всех данных

### Платная версия (расширенные возможности)
- Безлимитное AI-распознавание чеков
- Расширенный семантический поиск (улучшенное качество, больше источников)
- Расширенная аналитика и отчёты
- Синхронизация между устройствами
- Интеграции (Google Drive, Telegram, Email, PDF, голосовые заметки)
- Data Quality Score и рекомендации

**Принцип:** Платная версия добавляет удобство, но не является необходимой для базового использования. Бесплатная версия — полноценный продукт.
