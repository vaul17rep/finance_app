## Основная идея

Пользователь создаёт события в разных сферах жизни. Система структурирует, анализирует и помогает принимать решения.

Возможности:
- Фиксировать доходы и расходы
- Сохранять покупки, распознавать чеки
- Управлять счетами и бюджетом
- Анализировать состояние
- Вести заметки с семантическим поиском (система знаний)
- Настраивать AI-профили и цвета счетов
- Отслеживать фоновые задачи
- Оценивать качество данных

---

## Конфиденциальность

### Принципы
1. Локальное хранение: все данные пользователя хранятся только на его устройстве
2. Внешние вызовы: только для распознавания чеков и создания эмбеддингов (OpenRouter). Пользователь явно соглашается при первом использовании
3. Прозрачность: пользователь может просмотреть логи и увидеть, какие данные отправлялись вовне
4. Удаление: пользователь может удалить все свои данные в любой момент

### Настройки конфиденциальности
- Переключатель "Отправлять данные в AI" (по умолчанию включено, но с явным согласием при первом запуске)
- Кнопка "Очистить все данные" (с подтверждением)
- Кнопка "Экспорт всех данных" (локально)

## Модель распространения

### Бесплатная версия (полностью функциональна)
- Неограниченное количество операций, счетов, чеков
- Базовое распознавание чеков (ограниченное количество)
- Базовый семантический поиск
- Все основные настройки
- Локальное хранение всех данных

### Платная версия (расширенные возможности)
- Безлимитное AI-распознавание
- Расширенная аналитика (графики, отчёты, Data Quality Score)
- Синхронизация между устройствами
- Интеграции (Google Drive, Telegram, Email)
- Расширенная система знаний (глубокий анализ, инсайты)

**Принцип:** Платная версия добавляет удобство и расширяет возможности, но не является необходимой для базового использования.

## Пользовательские сценарии

### Чеки

**Добавление:**
- Фото → AI → Receipt → Operation
- Поддержка нескольких фото через черновик (Receipt Draft)
- Возможность объединить несколько фото в один чек

**Просмотр:**
- Список, Pull-to-refresh, детали
- Навигация: листание между чеками (вверх/вниз)

**Редактирование:**
- Магазин, дата, комментарий, товары (название, количество, цена, категория, комментарий)
- Сохранение → пересчёт суммы → обновление экрана
- Отмена: диалог "Выйти без сохранения?" (Остаться / Выйти)

**Удаление:**
- Подтверждение → удаление Receipt + ReceiptItem + Operation
- Настройка: возможность отключить удаление свайпом

### Операции

**Расход:** сумма, категория, счёт → сохранить
**Доход:** сумма, счёт → сохранить
**Перевод:** перемещение между счетами

**Просмотр:**
- История с сортировкой (по дате, сумме, магазину, типу)
- Фильтры (дата, категория, счёт)
- Режимы: все счета / текущий счёт / фильтры (запоминается)
- Навигация: листание между операциями с фильтрацией

**Связь:** каждая операция привязана к Account

**Редактирование:**
- Все поля доступны для изменения
- Человеческие названия операций

### Переводы

**Сценарий 1 — Перевод с карточки счёта (быстрый доступ)**
1. Пользователь на главном экране видит карусель карточек счетов.
2. На карточке нужного счёта нажимает иконку перевода (↔), расположенную справа от названия счёта.
3. Открывается экран перевода (`TransferScreen`) с предустановленным счётом-источником.
4. Пользователь выбирает счёт-назначения, вводит сумму (и опционально комментарий) и подтверждает перевод.

**Сценарий 2 — Перевод через FAB на экране операций**
1. Пользователь открывает экран операций (`OperationsScreen`).
2. Нажимает на отдельную плавающую кнопку (FAB) с иконкой перевода (↔), расположенную над основной FAB «Добавить операцию».
3. Открывается экран перевода (`TransferScreen`) без предустановленного счёта.
4. Пользователь выбирает счёт-источник и счёт-назначения, вводит сумму (и опционально комментарий) и подтверждает перевод.

**Результат перевода:**
- Система создаёт две операции: расход на счёте-источнике и доход на счёте-назначении.
- Обе операции имеют пометку «Перевод» (поле `transferId`).
- Переводы исключаются из статистики доходов и расходов, отображаются отдельной строкой «Переводы».
- Баланс счетов обновляется автоматически.

### Счета (Accounts)

**Создание:** название, тип (банковский, карта, наличные, другой, рабочий бонус)

**Полная настройка:**
- Свободно изменяемые: название, иконка, цвет, описание, порядок, основной счёт
- Изменяемые с предупреждением: тип счёта, начальный баланс (через механизм миграции)
- Неизменяемые: ID, валюта

**Просмотр:** листание как галерея (влево/вправо), баланс (из операций)
**Детали:** баланс, список операций, фильтрация

### Черновики чеков (Receipt Draft)

1. Пользователь открывает экран создания чека
2. Выбирает режим: "Новый чек" или "Черновик" (если есть сохранённые)
3. Добавляет одну или несколько фотографий (с камеры или галереи)
4. Фотографии можно удалять, менять порядок, заменять
5. Нажимает "Распознать"
6. Система обрабатывает все фото и объединяет результат в один Receipt
7. Создаётся одна операция (Operation)
8. Черновик сохраняется в истории (можно вернуться и отредактировать)

### Бюджет
- Выбор периода, план/факт расходов
- Настройка периода: фиксированная дата / от зарплаты до зарплаты / пользовательская

### Аналитика
- Выбор периода, доходы/расходы/баланс/графики
- Статистика роста цен
- Сравнение магазинов
- История цен на товары
- Отметка о необычных покупках

### Оценка качества данных (Data Quality Score / Health Score)

Система оценивает полноту и качество финансовых данных.

**Показатели:**
- Процент операций с категорией
- Процент операций с чеком
- Соотношение ручных операций и чеков
- Наличие неопознанных товаров
- Заполненность обязательных полей
- Возможные дубликаты

**Отображение:**
- На экране аналитики (общий показатель)
- Детализация по категориям и периодам
- Рекомендации по улучшению качества

### Настройки

**Принцип:** Все пользовательские сценарии не должны требовать изменения кода. Если настройка может быть полезна пользователю, она должна быть доступна через UI.

**Настройки (бесплатная версия):**
- Общие: тема, валюта
- Срок хранения фото (дни)
- Удаление свайпом (вкл/выкл)
- Режим по умолчанию для истории операций (все счета / текущий счет)
- Автоиндексация (вкл/выкл)
- Количество результатов семантического поиска
- Цвета карточек: выбор цвета фона для каждого счёта
- Фоновые задачи: просмотр состояния

**Настройки (платная версия):**
- Выбор AI-модели
- AI-профили: создание, редактирование, удаление, API-ключи, лимиты
- Расширенные настройки системы знаний

### Система знаний (Memory)

- Просмотр списка источников (Obsidian, внутренние заметки)
- Создание заметок (Markdown), редактирование, удаление
- Семантический поиск по смыслу, результаты с релевантностью и фрагментами
- Авто-индексация в фоне, отображение прогресса
- Индексация Obsidian Vault: выбор папки, ручной запуск
- Универсальный поиск по всем источникам одновременно
- Просмотр списка источников (Obsidian, внутренние заметки)
- Создание заметок (Markdown), редактирование, удаление
- Семантический поиск по смыслу, результаты с релевантностью и фрагментами
- Авто-индексация в фоне, отображение прогресса
- **Индексация Obsidian Vault:**
  - Выбор папки в настройках
  - Ручной запуск индексации по кнопке
  - **Инкрементальная индексация** (только изменённые файлы)
  - **Отображение прогресса** (обработано N из M)
  - **Отчёт по окончании** (успешно/пропущено/ошибок)
  - **Фильтрация служебных папок** (.trash, .obsidian, .git, .stversions)
- **Очистка битых эмбеддингов:** кнопка с подтверждением, предложение переиндексации
- **Копирование диагностического отчёта:** кнопка в диалоге диагностики

### Питание и инвентарь

**Управление продуктами:**
- Создание продукта: ручной ввод (название, категория, калорийность, БЖУ, единица измерения)
- Импорт продукта из чека: при распознавании чека пользователь может добавить товар (ReceiptItem) в базу продуктов
- Просмотр, редактирование, удаление продукта из базы

**Добавление приёма пищи (Meal):**
- Создание нового приёма: завтрак, обед, ужин, перекус
- Добавление продуктов в приём пищи: поиск по базе продуктов
- Автоматический расчёт калорий и стоимости приёма
- Возможность добавить продукты вручную (без приёма, как самостоятельное событие)

**Потребление и инвентаризация (UI-концепция):**
- При добавлении продукта в приём пищи (или отдельное событие) пользователь указывает общее количество
- Система предлагает интерактивный интерфейс (например, круговую диаграмму) для распределения количества на три состояния:
  - **Съедено** (eaten) — часть, которая была съедена
  - **Осталось** (remaining) — часть, которая осталась и будет храниться дома
  - **Выброшено** (wasted) — часть, которая была испорчена или выброшена
- Пользователь может изменять доли интерактивно (двигая сектора) или вводить значения вручную
- При сохранении:
  - Журнал питания (Meal) обновляется на основе "съеденной" части
  - Инвентарь (InventoryItem) обновляется на основе "оставшейся" части
  - Событие "выброшено" фиксируется для аналитики и не влияет на инвентарь или питание

**Управление инвентарём:**
- Просмотр текущих запасов продуктов с количеством и сроком годности (опционально)
- Использование продукта из инвентаря: при добавлении в приём пищи система автоматически уменьшает остаток и пересчитывает состояние
- Редактирование инвентаря: возможность вручную изменить количество, добавить или удалить продукт
- История изменений инвентаря (на основе FoodEntry)

**Аналитика питания:**
- Отчёты по калориям, БЖУ за период (день, неделя, месяц)
- Анализ расходов на питание
- Статистика по потерям (количество выброшенной еды)
- Сравнение планового и фактического питания

**Связь с системой знаний:**
- Продукты, приёмы пищи и инвентарь индексируются для семантического поиска (Memory)
- Пользователь может искать по описанию приёма или продукту: "что я ел на завтрак в прошлую среду"
- Система может предлагать инсайты на основе эмбеддингов (например, связь между питанием и самочувствием)

### Фоновые задачи
- Индексация, распознавание чеков, обновление данных
- Мониторинг списка активных/завершённых
- Плавающий виджет статуса на главном экране
- Отмена/перезапуск (если поддерживается)

### Логи (диагностика)

- **Доступ:** только в режиме разработчика (включён по умолчанию). Иконка жука на главном экране → переход к экрану логов.
- **Просмотр:** список записей с уровнем, тегом, временем и сообщением.
- **Фильтрация:** по уровню и тегу (работают по AND).
- **Копирование:** кнопка "Копировать всё" — копирует все отфильтрованные логи; долгое нажатие на запись — копирует только её.
- **Очистка:** кнопка "Очистить" — удаляет все логи (с подтверждением).
- **Шаринг:** кнопка "Поделиться" — отправляет файл `logs.txt` через системный диалог.
- **Сохраняемость:** логи сохраняются в файл и доступны после перезапуска.

### Диагностика Memory (для разработчиков)

Доступна в режиме разработчика через кнопку на экране Memory.
После запуска система:

1. Выполняет все зарегистрированные проверки.
2. Записывает результаты каждой проверки в `DebugLogger` с тегом `MEMORY`.
3. После завершения автоматически открывает экран `DebugLogScreen` с применённым фильтром `MEMORY`.
4. Разработчик использует стандартные инструменты логов для анализа.

## Ограничения

- Баланс не изменяется вручную — только через операции
- Операции — источник истины
- AI не принимает финансовых решений
- Требования не зависят от технологии
- Все данные локальные по умолчанию

## Непринятые решения

- ❓ Связь Receipt и Operation: один к одному (текущая) или один ко многим?
- ❓ Модель долгов: отдельная сущность или часть финансового состояния?
- ❓ Какие функции будут платными? (точный список)
- ❓ Механизм изменения начального баланса: через операцию или отдельный метод?
- ❓ Нужно ли шифровать локальную БД?
