## Начальная система

До Flutter — полноценная система учёта на Google Sheets. Не прототип, а первая версия системы.

Реализовано:
- Структура операций
- Бюджетные периоды
- Планирование и аналитика
- Учёт долгов и состояний
- Автоматические правила
- Обработка операций

Цель: видеть состояние, контролировать расходы, анализировать категории, планировать, учитывать долги, принимать решения на основе данных.

## Legacy Google Sheets

### Идея системы
**Операции — источник истины.**

Нельзя: КартаСбер = 15000 и менять число
Правильно: Зарплата +50000 → Продукты -5000 → Перевод -3000 → Состояние: КартаСбер = 42000

### Архитектура
Два листа - четыре части системы: Бюджет, Аналитика, Справочники, Интерфейс.

**Бюджет:** капитал (карты, наличные, общий, доступные), бюджетный период (от поступления до поступления, например 30.05 → 29.06), плановые/фактические расходы, остатки.

**Аналитика:** база операций (начало со строки 651). Структура: ID, дата, день, регулярность, тип (расход/доход), статья, категория, название, магазин, план, факт, рабочая сумма, тип оплаты, ID чека, количество, единица, цена, цена до скидки, экономия, дата окончания, комментарий.

Типы операций: Расход, Доход, Доп. расход, Доп. доход.
Типы оплаты: карта, наличные, кредит, перевод.

**Логика план/факт:** если есть факт → Рабочая сумма = Факт, иначе = План.

**Справочники:** категории, состояния, ключевые слова, правила, соответствия. Поиск через contains/includes. Пример: "оплата кредитка сбер Аня" находил правило "кредитка сбер" → КредиткаСбер.

**Интерфейс:** панель для ручного ввода, просмотра, управления периодами.

### Финансовые состояния
КартаСбер, Наличные, КредиткаСбер, Отложено, Долги. Вычислялись из операций.

- Дебетовая карта: доход → баланс+, расход → баланс-
- Кредитная карта: покупка → долг+, погашение → долг-
- Долги: статья "Долги" — расход → долг-, доход → долг+
- Накопления: Отложено — расход → отложено+, доход → отложено-
- Рабочая сумма: учитывала план, факт, скидки

### Долговая логика
Определение через статью, тип операции, комментарий. Поиск правила → состояние.

### Apps Script
Автоматизация: изменение состояний, обработка операций, новые периоды, архивирование, ручной ввод (ID: MAN-...), синхронизация.

### История изменений
Сохранение для отслеживания, откатов, понимания происхождения состояния.

## Причины перехода на Flutter

Google Sheets справлялась, но ограничения:
- Нужно мобильное использование
- Быстрое добавление расходов
- Фото чеков
- Автоматическое получение данных с чеков
- Сложность поддержки (формулы, скрипты)
- Сложность масштабирования
- Отсутствие разделения слоёв
- Неудобство создания приложения поверх таблицы

## Важные решения

1. **AI не имеет прямого доступа к БД** — разделение ответственности
2. **Экран не изменяет SQLite напрямую** — разделение UI и данных
3. **Фото не главный объект** — только для распознавания и проверки
4. **AI не создаёт финансовые состояния** — только распознавание, логика внутри приложения
5. **Приватность по умолчанию** — все данные локальные, внешние вызовы только с согласия пользователя (30.07.2026)
6. **Бесплатная работающая версия** — приложение полностью функционально без покупок (30.07.2026)
7. **Memory как универсальная система знаний** — единый слой для любых источников информации (30.07.2026)
8. **Receipt Draft** — черновик чека для объединения нескольких фото (30.07.2026)

## Историческое значение

Google Sheets доказала работоспособность идеи: Операции → Состояния → Аналитика. Эта система стала основой Flutter-приложения.

Проект эволюционировал от финансового учёта к операционной системе для жизни (LifeOS), объединяющей финансы, заметки, аналитику и AI-ассистента в едином локальном пространстве.
