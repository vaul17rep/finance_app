#### Type: Feature

**Изменение:** Интеграция точек входа для переводов между счетами

**Описание:**

- Пользователь может инициировать перевод в два клика с главного экрана.
- На экране операций появилась вторая FAB, упрощающая создание переводов.
- Существующая FAB «Добавить операцию» не затронута.

Feature / Bug Fix / Refactoring

**Изменение:**

Двухфазное улучшение системы знаний (Memory):

**Phase 1 — Стабильность:**

1. Добавлено логирование полного ответа OpenRouter при ошибках 400/403
2. Добавлена валидация текста в `EmbeddingService` (пустые и короткие тексты < 3 символов пропускаются)
3. Добавлена автоматическая очистка битых BLOB-векторов при инициализации `SqliteVectorSearchService`

**Phase 2 — Архитектурная эволюция:**

1. Изменён `sourceId` с пути на стабильный идентификатор документа (хеш пути) для Obsidian
2. Внедрена безопасная миграция с использованием `migrationId`:
   - Backup БД → создание нового индекса → валидация (порог 90%) → удаление старого → очистка `migrationId`
3. Интегрирован `ChunkingService` для файлов > 5000 символов с метаданными чанков
4. Добавлена группировка результатов поиска по `sourceId` (один документ → один результат)
5. Обновлён отчёт индексации (добавлены `totalChunks`, `oldRecordsDeleted`, `newRecordsCreated`)
6. Сохранение `metadata.path` для обратной совместимости

**Исправление критических проблем (Code Review):**

1. Атомарность операции: сначала создание чанков, потом удаление старых эмбеддингов
2. Метод возвращает `success` только если сохранён хотя бы один чанк
3. Инкрементальная проверка работает для больших файлов через `findAllBySourceId()`
4. Битые векторы удаляются асинхронно во время поиска

**Причина:**

- Низкое качество семантического поиска (отсутствие чанкинга для больших документов)
- Нестабильность индексации (потеря данных при частичных ошибках)
- Инкрементальная индексация не работала для больших файлов
- Битые BLOB-векторы вызывали ошибки при поиске

**Результат:**

- Индексация больших файлов (> 5000 символов) работает корректно через чанкинг
- Результаты поиска сгруппированы по документам (UX улучшен)
- Миграция безопасна: при неудаче старый индекс сохраняется
- Атомарность гарантирует отсутствие потери данных
- Инкрементальная индексация работает для всех типов файлов
- Битые векторы удаляются автоматически
- API-запросы не отправляются для пустых или слишком коротких текстов

### 2026-07-30
#### Type: Refactoring

**Изменение:** Интеграция Memory Diagnostics с общей системой DebugLogger

Диагностика памяти переведена с собственного окна результатов на существующую инфраструктуру логирования приложения.

`MemoryDiagnosticService` теперь логирует:
- запуск диагностики;
- начало каждой проверки;
- результат каждой проверки;
- ошибки выполнения;
- итог диагностики.

`DiagnosticButton` после завершения автоматически открывает `DebugLogScreen` с фильтром `MEMORY`.

**Причина:**
Избавиться от дублирования интерфейсов просмотра результатов, использовать единую систему логирования и упростить анализ диагностики.

**Результат:**
- единый источник диагностических логов;
- копирование полного журнала одним нажатием;
- использование существующих фильтров Debug;
- отсутствие дублирующего UI;
- более удобная отладка всех проверок Memory.

**Затронутые документы:**

### 2026-07-30
#### Type: Feature & Bug Fix
**Изменение:** Улучшение системы знаний (Memory) — инкрементальная индексация, пакетная обработка, исправление битых BLOB

**Описание:**
Реализован комплекс улучшений для системы знаний:

1. **Инкрементальная индексация Obsidian** — добавлена проверка `sourceUpdatedAt` vs `modifiedAt`; повторная индексация не пересоздаёт эмбеддинги для неизменённых файлов
2. **Пакетная обработка** — индексация файлов пачками по 30 с паузой 100 мс и параллельностью 5 запросов
3. **Прогресс в UI** — добавлен колбэк `onProgress` в `indexObsidian()`; отображение `обработано N из M` в AppBar MemoryScreen
4. **Отчёт после индексации** — диалог с количеством успешно/пропущено/ошибок и списком ошибок
5. **Очистка битых эмбеддингов** — кнопка в MemoryScreen; проверка существования таблицы; удаление записей с `LENGTH(vector) % 4 != 0`; предложение переиндексации
6. **Исправление битых BLOB** — `vectorToBlob()` и `blobToVector()` создают копии данных через `Uint8List.fromList()` для правильного выравнивания в памяти
7. **Исправление `_checkAndCleanEmbeddings()`** — использование `MemoryDatabase` вместо основной БД
8. **Фильтрация `.stversions/`** — добавлена в `ObsidianReaderService` и `cleanObsidianTrash()`
9. **Копирование диагностического отчёта** — кнопка в диалоге для копирования отчёта в буфер обмена

**Причина:** 
- Низкая производительность при индексации больших Vault (1000+ файлов)
- Отсутствие обратной связи для пользователя
- Битые эмбеддинги вызывали `RangeError` при поиске
- Мусорные файлы из `.stversions` попадали в индекс

**Результат:**
- Индексация 654 файлов выполняется за ~2 минуты с отображением прогресса
- Битые эмбеддинги удаляются автоматически при поиске и через UI
- Таблица `embeddings` проверяется перед операциями
- Пользователь получает отчёт по окончании индексации
- Устранены ошибки `RangeError: Offset must be a multiple of BYTES_PER_ELEMENT`

### 2026-07-30
#### Type: Architecture & Product Decisions
**Изменение:** Приняты ключевые архитектурные и продуктовые решения.

**Описание:**
В ходе обсуждения утверждены следующие решения:

1. **Переименование проекта в LifeOS** — проект эволюционирует от финансового учёта к операционной системе для жизни.

2. **Полная конфиденциальность** — все данные локальные, внешние вызовы только с согласия пользователя, только для конкретных функций, данные не сохраняются на стороне провайдера.

3. **Бесплатная работающая версия** — приложение полностью функционально без покупок. Платные функции — расширения (аналитика, интеграции, улучшенный AI).

4. **Memory как универсальная система знаний** — единая система для любых источников (Obsidian, внутренние заметки, PDF, Telegram, и др.). Введение абстракции KnowledgeSource.

5. **Receipt Draft** — черновик чека для объединения нескольких фото в один чек с полноценным жизненным циклом.

6. **Полная настройка счетов** — принципы изменяемости полей: свободно изменяемые (название, цвет, порядок), изменяемые с последствиями (тип счёта, начальный баланс), неизменяемые (ID, валюта).

7. **Data Quality Score** — система оценки полноты и качества данных (Health Score).

8. **Все настройки через UI** — принцип баланса между гибкостью и простотой.

9. **Семантический поиск** — реализован, но качество требует доработки (без предположений о причинах).

10. **Obsidian-ссылки в документации** — использование внутренних ссылок Obsidian [[название]].

**Причина:** Устранение неопределённостей, синхронизация видения проекта.

**Результат:** Чёткая архитектурная и продуктовая стратегия на ближайшее будущее.

**Затронутые документы:** все 00–11

### 2026-07-27
#### Type: Feature / Bug Fix
**Изменение:** Очистка и защита индекса Obsidian embeddings

**Описание:**
В рамках стабилизации системы знаний реализована фильтрация мусорных файлов при индексации Obsidian Vault. В ObsidianReaderService._findMarkdownFiles() добавлено исключение директорий .trash, .obsidian, .git и файлов с суффиксом .sync-conflict-*. В IndexingService добавлен метод cleanObsidianTrash(), который удаляет уже существующие эмбеддинги, чей путь содержит /.trash/ или /.obsidian/. Очистка выполняется автоматически перед каждой индексацией Obsidian.

**Причина:**
При первой индексации в базу попали служебные файлы из корзины и конфигурационных папок Obsidian, что засоряло поиск и увеличивало размер индекса.

**Результат:**
- Старые мусорные эмбеддинги удалены.
- Новые индексы строятся только на полезных заметках.
- Повторная индексация не пересчитывает все заметки заново.
- База памяти Obsidian стала консистентной и чистой.

**Затронутые документы:**
- 01_Current_State
- 06_AI_System
- 07_Functional_Requirements

- 09_Development_Log (эта запись)
