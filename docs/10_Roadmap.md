Не строгий календарный план — приоритеты могут меняться.

---

## Общая стратегия развития

Надёжная модель данных → Ввод и управление → Финансовая логика → Аналитика и автоматизация → Единый личный помощник (финансы + заметки + питание + планы + память + ИИ)

**Главная цепочка:**
Receipt → ReceiptItem → Operation → Financial Rules → Budget → Analytics → AI / Система знаний

**Источник истины:** Operation. Чеки — один из способов создания операций. Заметки и другие материалы — через систему знаний.

---

## Ключевые принципы развития

- **Приватность по умолчанию:** все данные локальные, внешние вызовы только с согласия пользователя.
- **Бесплатная работающая версия:** приложение полностью функционально бесплатно. Платные функции — расширения.
- **Memory как универсальная система знаний:** единый слой для любых источников информации.
- **Все настройки через UI:** пользовательские сценарии не должны требовать изменения кода.
- **Мягкое управление:** приложение возвращает к жизни, а не контролирует. Уведомления — с выбором действия, просроченные задачи не исчезают.
- Процесс разработки и роли описаны в [[11_Development_Guidelines]].

## Phase 4.1 — Бонусные/виртуальные счета

**Цель:** Поддержка любых бонусных программ (кешбэк, бонусы магазинов, подарочные карты, рабочий лимит).
**Статус:** 📅 ЗАПЛАНИРОВАНО

### Основная идея
Пользователь видит единый источник оплаты (например, «Бонусы» или «Рабочий лимит»). Приложение само ведёт внутреннюю математику.

### Архитектурные принципы
- **Account остаётся неизменным** — только реальные финансовые счета
- **Бонусная программа** — отдельная сущность, не наследующая Account
- **Operation — единый источник истины** — добавляются поля для бонусной части
- **Остаток не хранится** — всегда вычисляется из истории операций
- **Ленивое обновление** — при первом обращении

### Открытые вопросы
- ❓ Название сущности: CreditProgram / WorkBenefitProgram / EmployerBenefitProgram / WorkAllowance / EmployeeBenefit
- ❓ Название поля для накопленной части: accumulatedAdvance / availableBalance
- ❓ Отображение остатка в виджете выбора: не показывать / показывать всегда / только при низком остатке

## Phase 7.2 — Интеллектуальная система знаний (Second Brain)

**Цель:** Превратить поток мыслей пользователя в организованную базу знаний.

### Главный принцип
> Сначала думать и рассказывать → потом система организует.

### Три слоя данных
1. **Original Layer** — оригинальный рассказ пользователя (источник истины, не редактируется ИИ)
2. **Archive Layer** — структурированная версия (ИИ как архивист, без анализа)
3. **Intelligence Layer** — анализ ИИ (гипотезы, наблюдения, вопросы, отдельно от данных)

### Интеграция с Obsidian
- Режим 1 — виртуальная организация (приложение не изменяет структуру Vault)
- Режим 2 — автоматическая организация (опционально, по правилам пользователя)

### Режимы ИИ
- Archive — только структурирование
- Analysis — наблюдения, вопросы, закономерности
- Connections — поиск похожих мыслей через эмбеддинги
