## Общая стратегия развития

**Приоритет 1 (сейчас):** Финансовое ядро — надёжный учёт денег.
**Приоритет 2 (следующий):** Планирование и задачи — To‑Do, планы покупок, напоминания.
**Приоритет 3 (потом):** Заметки и интеллектуальный поиск — система знаний.
**Дополнительно (параллельно с Приоритетом 2–3):** Пользовательские поля — расширение любых сущностей для кастомизации учёта.

**Главная цепочка:**
Receipt → ReceiptItem (с категориями) → Operation → Счета → Бюджетные периоды → Долги → Планы → Аналитика

**Источник истины:** Operation. Всё остальное — надстройки.

---

## Ключевые принципы развития

- **Приватность по умолчанию:** все данные локальные, внешние вызовы только с согласия пользователя.
- **Бесплатная работающая версия:** приложение полностью функционально бесплатно. Платные функции — расширения.
- **Все настройки через UI:** пользовательские сценарии не должны требовать изменения кода.
- **Мягкое управление:** приложение возвращает к жизни, а не контролирует. Уведомления — с выбором действия, просроченные задачи/долги не исчезают.
- **Кастомизация без кода:** пользователь может добавлять собственные поля к любым сущностям (операции, чеки, заметки) через UI.

## Архитектурные решения (принятые)

### Категории

- Категория — только у ReceiptItem. У чека категории нет.
- Отдельная таблица `categories` с пользовательскими категориями.
- При анализе группировка по категориям товаров.

### Долги

- Отдельная сущность `Debt` (таблица `debts`), не часть Financial State.
- Погашение → создаётся Operation типа `debt_repayment`, связанная с `debtId`.
- Отдельная таблица `debt_payments` для истории частичных погашений.
- Просроченные долги не исчезают, пока не закрыты вручную.

### Бюджет

- Период: пользовательский (по умолчанию от зарплаты до зарплаты).
- `budget_periods` + `budget_items` (план по категориям).
- Расходы считаются из операций по категориям.
- Платежи по долгам — отдельная категория в бюджете.

### Пользовательские поля (новое)

- Пользователь может добавлять произвольные поля к сущностям: **Operation**, **Receipt**, **ReceiptItem**, **MemoryNote**.
- Типы полей: `text`, `number`, `date`, `boolean`, `select` (список), `multiselect`.
- Поля отображаются в карточке/детализации, участвуют в фильтрации и отчётах.
- Не влияют на финансовую логику — только метаданные.

**Цель:** Управление плановым бюджетом.

**Модель:**

- `budget_periods`: id, name, startDate, endDate, status (active/archived)

**Функциональность:**

- [ ] Период: пользовательский (по умолчанию от зарплаты до зарплаты)

- [ ] Остаток: доходы − расходы − плановые накопления
- [ ] Прогресс-бары по категориям
- [ ] Предупреждения при 80%/100% лимита
- [ ] История периодов с возможностью сравнения

### Phase 4 — Долги и обязательства

**Цель:** Полноценный учёт долгов и регулярных платежей.

**Модель:**

- `debts`: id, counterparty, amount, currency, type (owed_to_me/i_owe), date, dueDate, status (active/partial/closed/overdue), originalAmount, comment
- `debt_payments`: id, debtId, amount, date, comment
- `recurring_payments`: id, name, amount, categoryId, startDate, endDate, frequency, accountId

**Функциональность:**

- [ ] **Долги:**
  - Создание, редактирование, закрытие
  - Частичное погашение с историей
  - Напоминания о сроках
  - Просроченные не исчезают
  - При погашении → создаётся Operation (тип `debt_repayment`)
- [ ] **Обязательные платежи:**
  - Регулярные списания (аренда, подписки)
  - Авто-создание операций
- [ ] **Планы покупок:**
  - Цель накопления, прогресс
  - Связь с операциями

## Дополнительный модуль (параллельно)

### Phase 11 — Пользовательские поля (НОВОЕ)

**Цель:** Дать пользователю возможность добавлять произвольные поля к любым сущностям (Operation, Receipt, ReceiptItem, MemoryNote) для кастомизации учёта.

**Модель:**

- `custom_field_definitions`: id, entityType (operation/receipt/receiptItem/memoryNote), fieldName, fieldType (text/number/date/boolean/select/multiselect), options (JSON для select), isRequired, defaultValue
- `custom_field_values`: id, entityId, definitionId, value (JSON — универсальное хранение)

**Функциональность:**

- [ ] Управление определениями полей (создание, редактирование, удаление) через UI
- [ ] Отображение полей в карточках сущностей
- [ ] Фильтрация и сортировка по пользовательским полям в списках
- [ ] Участие в отчётах (группировка, суммы)
- [ ] Экспорт/импорт определений (JSON)

**Этапы внедрения:**

1. **Phase 11.1** — Пользовательские поля для операций (база)
2. **Phase 11.2** — Расширение на чеки, товары, заметки
3. **Phase 11.3** — Отчёты и фильтры по пользовательским полям
