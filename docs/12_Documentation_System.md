## Что такое система документации

Документация — это не просто набор файлов. Это система, которая:

1. Хранит знания о проекте
2. Обеспечивает единое понимание
3. Помогает принимать решения
4. Снижает когнитивную нагрузку
5. Является частью процесса разработки

---

## Принципы системы документации

### Принцип 1 — Один факт = один источник
Информация хранится в одном месте. Дублирование запрещено. Если нужно сослаться — используется ссылка.

### Принцип 2 — Документация живёт рядом с кодом
Документация находится в репозитории проекта и обновляется вместе с кодом. Изменение кода без обновления документации считается неполным.

### Принцип 3 — Документация проверяема
Существуют инструменты автоматической проверки: валидация ссылок, проверка версий, проверка терминологии.

### Принцип 4 — Документация измерима
Есть метрики здоровья: покрытие, актуальность, связанность, долг документации.

### Принцип 5 — Документация доступна для поиска
Документация индексируется через ту же систему эмбеддингов, что и пользовательские данные. Можно искать по смыслу.

### Принцип 6 — Документация для разных ролей
Разделы помечаются тегами ролей (`@dev`, `@arch`, `@user`). Каждый читатель видит релевантное.

### Принцип 7 — Процесс как часть документации.
Процесс разработки документируется в `11_Development_Guidelines` и `12_Documentation_System`. Обновление процесса требует обновления этих документов по тому же процессу.

## Инструменты системы документации

### Автоматическая валидация
Скрипт `scripts/validate_docs.py` проверяет:
- Существование всех `[[ссылок]]`
- Наличие полей `Version:` и `Last Updated:`
- Синхронность дат обновления при глобальных изменениях
- Единообразие терминологии

Запускается вручную или через pre-commit hook.

### State Snapshot
Скрипт `scripts/generate_snapshot.py` собирает информацию из всех документов и генерирует `99_State_Snapshot.md`:
- Что реализовано (из `01_Current_State`)
- Что в работе (из `10_Roadmap`)
- Открытые вопросы (из всех `❓`)
- Технический долг (из `02_Architecture`)
- Последние изменения (из `09_Development_Log`)

### Метрики здоровья
Скрипт `scripts/docs_health.py` вычисляет:
- Покрытие требований (реализовано / всего FR)
- Актуальность (средний возраст документов)
- Связанность (среднее количество ссылок)
- Долг документации (разделы, не обновлённые > 30 дней)

Генерирует `docs/health_report.md`.

### Связь с кодом
Файл `docs/code_mapping.yaml` содержит соответствия между файлами кода и разделами документации.
Скрипт `scripts/check_sync.py` проверяет, что документация обновлена вместе с кодом.

### Индексация документации
Документация индексируется через ту же систему эмбеддингов, что и пользовательские данные.
Поиск по документации доступен через Memory Screen (режим "Документация").

## Чек-лист обновления

При изменении любого аспекта проекта используется чек-лист из `docs/update_checklist.md`:

**При изменении модели данных:**
- [ ] Обновить `03_Domain_Model`
- [ ] Обновить `05_Database_Specification`
- [ ] Обновить `07_Functional_Requirements` (если меняется поведение)
- [ ] Добавить запись в `09_Development_Log`

**При изменении архитектуры:**
- [ ] Обновить `02_Architecture`
- [ ] Обновить `11_Development_Guidelines` (если меняются правила)
- [ ] Добавить запись в `09_Development_Log`

**При добавлении новой функции:**
- [ ] Добавить требование в `07_Functional_Requirements`
- [ ] Обновить `10_Roadmap`
- [ ] Добавить запись в `09_Development_Log`
- [ ] Обновить `01_Current_State`

**При изменении AI или системы знаний:**
- [ ] Обновить `06_AI_System`
- [ ] Обновить `03_Domain_Model` (если добавляются сущности)
- [ ] Обновить `05_Database_Specification` (если добавляются таблицы)
- [ ] Добавить запись в `09_Development_Log`

## Связь с проектом

Система документации является частью проекта LifeOS и следует тем же принципам:

- **Приватность по умолчанию** — документация хранится локально
- **Бесплатная версия** — документация открыта для всех участников
- **Один факт = один источник** — информация не дублируется
- **AI не владелец данных** — документацию пишут люди, AI помогает структурировать
