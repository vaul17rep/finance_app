# CHANGE PROTOCOL

Назначение:

Правила синхронизации документации после изменений системы.

Документация является частью системы LifeOS.

После каждого изменения необходимо определить:

- какие области затронуты;
- какие документы требуют проверки;
- какие документы требуют обновления.

---

# General Rule

Любое изменение должно пройти цикл:

1. Код изменён.
2. Определены затронутые области.
3. Проверены связанные документы.
4. Пройден Code Review.
5. Knowledge Manager синхронизировал документацию.
6. Изменение записано в историю.
7. AI Context Layer проверен и обновлён при необходимости.

---

# Documentation Ownership

Каждый факт должен иметь один источник истины.

Перед изменением документа определить:

- какой факт изменился;
- какой документ является владельцем этого факта;
- требуется ли обновление связанных документов.

Не создавать:

- дублирование информации;
- альтернативные описания одной системы;
- устаревающие инструкции.

---

# Responsibility

## Developer

Отвечает за:

- сообщение изменённых файлов;
- указание новых компонентов;
- указание миграций;
- подготовку Implementation Report.

---

## Code Reviewer

Отвечает за:

- проверку соответствия реализации;
- проверку влияния изменений;
- передачу полного пакета Knowledge Manager.

---

## Knowledge Manager

Отвечает за:

- анализ влияния изменений на документацию;
- обновление документов;
- обновление истории;
- проверку AI Context Layer;
- отсутствие противоречий.

---

☐ Документы проверены

☐ Необходимые документы обновлены

☐ История обновлена
